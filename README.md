# MST 파운데이션 달란트

빌드 단계 없이 동작하는 HTML/CSS/JavaScript 서비스입니다. QR 생성·인식 라이브러리는 vendor/에 포함되어 있습니다. [출처와 라이선스](vendor/README.md)를 함께 기록합니다.

잔액과 결제는 Mustree 체인(7601)에 발행한 ERC-20 토큰 **wMST**(1 wMST = 1원, 소수점 없음)로 처리하고, 네이티브 MST는 수수료에만 씁니다. 손님·가게 화면은 토큰·체인 용어 없이 “MST”라는 브랜드명과 원화만 보여줍니다.

## 화면과 공통 구조

- index.html: 개인 지갑 잔액, 충전용 받기 QR, 최근 거래
- preview.html: 지갑 연결 없이 화면 상태와 결제 흐름을 확인하는 미리보기
- operator.html: 직원이 현금을 받고 손님 지갑으로 wMST와 수수료를 한 번에 충전
- pay.html: 가게 결제 또는 mode=transfer인 일반 송금
- store.html: 가게 받기 QR, 잔액, 최근 거래, 공통 송금 화면으로 이동
- merchant.html: 연결 없이 주소를 입력해 가게 받기 QR 생성
- dashboard.html: 운영자용 현황판. 발행·충전·회수·결제 합계, 지갑별 잔액과 수수료 잔여, 최근 거래를 모바일에서 확인
- setup.html: 운영자용. wMST 발행과 실제 수수료 측정, wallet.js에 넣을 설정값 생성

송금은 역할에 관계없이 transfer-core.js의 검증·전송·영수증 확인을 사용합니다.
transfer-page.js가 지갑 연결과 송금 상태를 관리하고 payment-ui.js가 공통 입력·대기·완료 화면을 만듭니다.
금액 계산, 토큰 호출 데이터 생성, 수수료 지원 정책은 transfer-core.js에서 처리합니다. 결제·충전 페이지는 HTML의 data-transfer-kind로 역할만 지정합니다.
QR 카메라·이미지 인식은 qr-scanner.js, QR 생성과 금액·주소 표시는 payment-ui.js로 통일했습니다.
개인·가게 내역의 조회와 계정별 갱신은 transaction-history.js, 표시는 payment-ui.js를 공유합니다.
계정이 바뀌거나 연결이 해제되면 이전 내역 응답은 무시하며 조회 실패를 빈 내역으로 표시하지 않습니다.

## wMST 토큰과 수수료

- 컨트랙트: [contracts/wMST.sol](contracts/wMST.sol). 고정 발행량을 배포 시 배포 지갑(운영 지갑)에 한 번에 발행하며 소유자·추가 발행·소각·정지 기능이 없습니다. 추가 발행 트랜잭션과 관리 코드가 없어 배포·전송 gas가 가장 적고 현장에서 관리할 것도 없습니다. 발행량은 setup.html에서 정하며 기본 1,000,000,000 wMST입니다(운영 지갑에 남은 토큰은 비용이 들지 않습니다).
- `transferWithGas(to, value)`: 충전 전용. wMST 전송과 함께 보낸 네이티브 MST(msg.value)를 같은 지갑으로 넘겨 **승인 한 번**으로 wMST와 수수료를 함께 충전합니다.
- 컴파일: solc 0.8.28, optimizer(runs 10000), evmVersion paris. 체인이 PUSH0을 거부하므로 Shanghai 이후 opcode를 쓰지 않습니다. 결과는 [contracts/wMST.artifact.json](contracts/wMST.artifact.json)과 setup.html이 쓰는 wmst-artifact.js에 커밋하며 테스트가 소스 해시와 함수 선택자를 대조합니다.
- 배포: 2026-10-23, 컨트랙트 0x2affeb7a958851645092cce8de9d2dbc88f2adf1, 배포 블록 13,341,971, 발행량 1,000,000,000 wMST(운영 지갑 보유). 설정은 wallet.js의 `TOKEN`(`address`, `deployBlock`, `gasPolicy`)에 있으며, `address`가 null이면 지갑 화면은 “서비스 준비가 아직 끝나지 않았어요”를 표시합니다. 발행·측정·설정 절차는 [DEPLOY.md](DEPLOY.md)를 참고하세요.

수수료 정책은 다음과 같습니다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 전송 요청에 넣는 수수료 상한 | maxFeePerGas 1,000 wei, maxPriorityFeePerGas 100 wei | 체인 base fee 7 wei, priority 100 wei(eth_gasPrice 107 wei). 지갑이 자체 추정값 대신 이 상한을 쓰도록 요청해 실제 비용을 107 wei/gas 수준으로 유지 |
| 전송 1회 확보 금액 `transferReserveWei` | 51,632,000 wei | 최악 조건(처음 받는 지갑) 전송의 MetaMask 가스 한도 51,632 × 상한 1,000 wei. 지갑은 이 금액 이상을 보유해야 전송을 허용 |
| 충전 1회 운영 지갑 확보 금액 `topUpReserveWei` | 88,472,000 wei | 처음 받는 지갑 충전의 가스 한도 88,472 × 1,000 wei |
| 충전 시 손님에게 주는 수수료 | `transfersPerTopUp`(20) × `transferReserveWei` = 1,032,640,000 wei | 요구사항: 충전 1회당 wMST 전송 20회분. 매 충전마다 고정으로 동봉 |

위 수치는 2026-10-23 setup.html에서 MetaMask가 실제로 보낸 거래 3건으로 측정한 값입니다: 새 지갑 전송 51,240 gas 사용/51,632 한도, 기존 지갑 전송 34,140/34,498, 충전 85,701/88,472. MetaMask는 요청한 상한 1,000 wei를 그대로 썼고 실제 지불은 107 wei/gas로 전송 1회 5,482,680 wei(5.5×10⁻¹² MST)입니다. 손님은 수수료 상한까지 오르는 최악의 경우에도 20회, 현재 체인 상태에서는 약 178회를 전송할 수 있습니다. 배포 전 추정은 `node tools/estimate-wmst-gas.cjs`(전송 51,440 gas, 충전 88,278 gas)로 측정값과 거의 같았습니다.

MetaMask가 `-32602`와 EIP-1559 미지원이라는 정확한 파라미터 검증 오류로 거절하면 결제·송금·충전은 계정·체인·잔액을 다시 확인하고 `gasPrice=1,000 wei`인 기존 수수료 형식으로 한 번만 재요청합니다. 이 경우 실제 단가가 1,000 wei이므로 위의 약 178회 대신 기존 20회분 확보 정책을 기준으로 봅니다. 취소·RPC 통신 오류·전송 결과가 불분명한 오류에는 이 재요청을 하지 않습니다. Android의 `RPC endpoint returned too many errors` 및 `ERR_NAME_NOT_RESOLVED`는 승인 대기와 구분해 통신 오류로 안내합니다. 공개 RPC 잔액 조회가 성공해도 MetaMask 자체 RPC의 서명·전송·결과 조회까지 복구되는 것은 아닙니다.

송금 전 검증은 wMST 잔액(부족 시 `INSUFFICIENT_BALANCE`)과 네이티브 MST 잔액(전송 확보 금액 미만이면 `INSUFFICIENT_GAS`)을 따로 확인합니다. 손님에게는 “수수료 잔액이 부족해요. 직원에게 충전을 요청해 주세요.”, 충전 화면에는 운영 지갑의 MST·wMST 보충 안내를 보여줍니다. 충전 화면은 운영 지갑의 MST로 가능한 충전 횟수를 “수수료 잔량”으로 표시합니다.

## 송금 정책

| 종류 | 입력 | 송금 내용 |
| --- | --- | --- |
| 가게 결제 | 원화 정수, 최대 10,000,000원 | 입력한 원화와 같은 수의 wMST를 `transfer`로 전송 |
| 직원 충전 | 1원 이상 정수, 운영자가 받은 현금 그대로 입력 | 같은 수의 wMST와 수수료 20회분 MST를 `transferWithGas`로 한 번에 전송. 자동 보너스 없음 |
| 일반 송금 | MST 정수 | 입력한 수의 wMST를 `transfer`로 전송 |

실제 모드에서는 MetaMask 승인을 통해 토큰 컨트랙트를 호출합니다. 전송 요청에는 체인 ID와 수수료 상한을 명시합니다.
계정·네트워크를 잔액 조회 전후로 재검증하고, 잔액 조회 실패 시 공개 RPC 조회를 지원합니다.
송금 결과 확인이 지연되면 기존 거래 해시만 다시 확인하며 새 송금을 막습니다. 거래 해시는 손님·가게 화면에 보이지 않고 진단 기록에만 남습니다.
금액은 모든 화면에서 정수 wMST를 천 단위 구분으로 표시하며 반올림이 없습니다. 잔액 아래의 “원 상당”은 같은 숫자입니다.

거래 내역은 토큰 컨트랙트의 Transfer 이벤트 로그(eth_getLogs)에서 계정이 보낸 것과 받은 것을 조회합니다. 최초 조회는 최근 43,200개 블록(2초 블록 기준 하루)을 확인하고, 이후에는 마지막 조회 완료 블록 다음부터 최신 블록까지 50,000개 블록 단위로 조회합니다. 배포 블록 이전은 조회하지 않습니다. 표시 건수와 관계없이 요청 범위를 모두 확인한 후에만 완료 블록을 갱신합니다. RPC 오류가 나면 기존 내역과 완료 블록을 유지합니다.
내역의 잔액 열은 해당 거래 직후 잔액입니다. 조회 범위의 마지막 블록에서 읽은 잔액에서 이벤트를 거꾸로 되짚어 계산하므로 과거 상태 조회가 필요 없고, 저장된 전송 해시로 범위 밖에서 복구한 거래만 —로 표시합니다.
내역 RPC의 각 HTTP 요청은 응답 본문 수신까지 8초로 제한합니다. 조회가 실패하면 오류 알림 없이 같은 완료 블록부터 한 번 더 시도하며, 총 두 번 실패했을 때 오류 안내와 ‘다시 확인’ 버튼을 표시합니다. 이전 오류 안내는 재시도 중에도 유지하고 버튼을 잠시 비활성화하며 성공할 때 해제합니다. 실패 기록은 재접속 후에도 유지하여 잔액이 같아도 재조회를 생략하지 않습니다.
체인·계정별 localStorage(bazaar-sync-v2)에 최근 24시간 내역 최대 200건, 조회 완료 블록, 그 블록의 wMST 잔액, 확인 시각을 함께 저장합니다. 네이티브 MST 시절의 v1 캐시는 읽지 않습니다. 개인 화면은 최근 5건, 가게 화면은 최근 20건을 표시합니다. 미리보기 내역은 저장하지 않습니다.
페이지 진입·복귀 시 현재 잔액을 조회하되, 이전 동기화 잔액과 같고 60초가 지나지 않았으며 미확인 전송 hash가 없으면 거래 내역 RPC를 생략합니다. 개인 지갑 화면이 보이는 동안에는 60초마다 잔액과 내역을 확인합니다. 가게 화면은 5초마다 잔액을 확인하고 잔액이 바뀌면 거래 내역도 자동 조회합니다. 잔액이 같아도 마지막 내역 동기화 후 60초가 지나면 내역을 확인합니다. 가게 화면의 자동 갱신은 QR과 가게 이름 입력창을 유지하며 잔액과 내역만 변경합니다. 잔액 새로고침과 내역 재시도는 잔액 변화와 관계없이 내역을 확인합니다. 숨겨진 페이지에서는 정기 요청을 보내지 않습니다.
직접 보낸 tx hash는 MetaMask에서 받은 즉시 별도 localStorage에 체인·발신 계정별로 저장합니다(24시간, 최대 200건). 미확인 hash는 다음 내역 갱신에서 영수증을 확인하며 영수증의 Transfer 로그로 범위 밖의 성공 거래도 복구합니다. 대기 중인 hash는 다음 확인 대상으로 유지하며 실패한 거래는 성공 내역에 넣지 않습니다.
저장 내역은 같은 브라우저에서만 유지됩니다. 다른 기기나 브라우저와 동기화되지 않으며, 브라우저 데이터 삭제 시 초기화됩니다. 네이티브 MST(수수료) 이동은 내역에 포함하지 않습니다.

## 운영 현황 (dashboard.html)

운영자가 휴대폰에서 지갑과 토큰 흐름을 한눈에 보는 읽기 전용 화면입니다. 지갑 연결 없이 공개 RPC에서 토큰의 Transfer 로그 전체(배포 블록부터, 50,000개 블록 단위)를 읽습니다. 운영자 지갑은 발행 로그의 수신자(배포 지갑)와 wallet.js `TOKEN.operatorWallets`에 적은 주소입니다. 운영자 지갑에서 나간 전송은 충전, 운영자 지갑으로 들어온 전송은 회수, 그 밖의 전송은 송금으로 봅니다.

- 카드 4개: 충전 합계·건수, 결제(지갑 간 송금) 건수, 지갑 수(가게 수 포함), 회수 합계·건수
- 지갑 표: #(첫 충전 순서로 매기는 번호), 지갑 주소(앞 5자리·뒤 5자리), 잔액, 사용 금액(그 지갑이 보낸 총액), 충전(운영자에게서 받은 총액), 최근 사용(충전·보낸 것·받은 것 중 가장 최근). 기본은 번호순이며 잔액·사용 금액·충전·최근 사용 머리글을 누르면 그 열로 정렬하고 다시 누르면 방향이 바뀝니다. 금액은 단위 없이 정수로 표시합니다. 운영자 지갑으로 토큰을 보낸 적이 있는 지갑에는 ‘회수’ 태그가 붙습니다.
- 행을 누르면 팝업에 전체 주소·복사, 잔액·충전·사용·받은 금액·운영자에게 보낸 금액·거래 수·최근 사용 시각·남은 수수료 횟수(그 지갑의 MST만 그때 조회)가 보이고 ‘가게로 설정’으로 가게를 지정합니다. 가게는 번호 없이 ‘가게’ 태그로 표의 맨 위에 옵니다. 가게 지정은 서버가 없으므로 그 휴대폰 브라우저의 localStorage에만 저장됩니다.
- 최근 거래 50건: 시간, 충전/송금 구분, 보낸 지갑 → 받은 지갑(운영·가게 표시), 금액

운영 흐름: 손님은 가게에 토큰을 모두 쓰는 것이 기본이고, 남은 토큰은 운영자에게 가서 QR로 운영자 지갑에 보내고 현금으로 돌려받습니다. 그 전송이 회수로 집계됩니다. 화면이 보이는 동안 10초마다 새 로그를 증분 조회하고 숨겨지면 멈춥니다. `?preview=1`은 예시 데이터를 표시합니다.

## 지갑 연결

- 서비스: https://bazaar.mustree.kr/
- 실제 지갑 사용 페이지(개인 지갑, 가게, 결제·일반 송금, 직원 충전)는 진입 시 현재 계정·체인을 확인하고 필요한 계정 연결과 Mustree 추가·전환 승인을 자동 요청합니다.
- 앱 복귀(focus·visibilitychange), 뒤로 가기 캐시 복원, 계정·체인·provider 연결 변경에서도 공통 컨트롤러가 재검증합니다. 이미 연결된 계정과 Mustree에는 추가 승인을 요청하지 않습니다.
- 승인 취소(4001)·기존 요청 대기(-32002) 뒤에는 같은 탭의 페이지 이동·복귀에서도 자동 팝업을 반복하지 않습니다. 기존 요청을 확인한 뒤 화면 또는 진단 패널의 ‘지갑 연결 다시 시도’를 눌러 재요청합니다. 수동으로 올바른 계정·체인에 연결하면 자동 확인 후 정상 상태로 복구합니다.
- 잔액 조회는 토큰 컨트랙트의 balanceOf(eth_call)와 네이티브 잔액(eth_getBalance)을 함께 읽습니다. MetaMask provider 읽기가 실패하면 공개 RPC 배치 요청으로 대체합니다.
- 결제 버튼은 매번 연결과 네트워크를 재검증하고, 전송 직전에도 계정·체인을 확인합니다. 전송 요청에 체인 ID를 명시합니다.
- 받은 거래 해시는 영수증 조회 전 계정·체인별 localStorage에 저장합니다. 결과 조회 실패·타임아웃·잘못된 영수증·다른 체인에서는 해시를 유지하고 재전송을 막습니다. 새로고침 후에도 다음 결제 시 기존 해시의 결과만 먼저 확인합니다. 저장소가 차단되거나 삭제되면 페이지 간 복구는 보장할 수 없습니다.
- 모바일 일반 브라우저는 MetaMask 내부 브라우저로 이어집니다.
- 네트워크 설정은 wallet.js의 NETWORK, 토큰·수수료 설정은 TOKEN에서 관리합니다.

RPC: https://block.mustree.kr, Chain ID: 7601 (0x1db1), 기호: MST, decimals: 18, 블록 간격 약 2초.

공개 RPC 잔액·내역 요청은 각각 8초, MetaMask provider 읽기 요청은 12초로 제한합니다. `node tools/measure-rpc.cjs`로 실제 응답 시간을 다시 측정할 수 있습니다. 결과는 Git에서 제외되는 measurements/rpc-latency.json에 저장됩니다. 이전 PC 표본의 HTTP 요청 61회는 모두 성공했고, 100개 블록 묶음 최대 31.7ms, 잔액 조회 최대 1,014.9ms였습니다. 모바일 회선과 거래가 많은 블록은 이 표본에 포함되지 않았습니다.

## 미리보기와 테스트

개인 지갑 미리보기는 `preview.html`에서 제공합니다. 기존 `/?preview=1` 링크는 화면 상태를 유지해 이 페이지로 이동합니다. 결제·충전·가게·운영 현황·설정 화면은 URL에 `?preview=1`을 붙여 확인할 수 있습니다. 미리보기에서는 실제 지갑 조회·승인·송금을 실행하지 않습니다.
개인 지갑 미리보기는 상태 선택기로 승인·취소·실패·지연 상황을 재현합니다.
미리보기 QR은 실제 송금에 사용할 수 없는 안내 그림입니다.

Node.js 22 이상과 Python 3을 사용합니다. 앱 실행과 테스트에는 패키지 설치나 빌드 과정이 없습니다. 컨트랙트를 다시 컴파일할 때만 `npm install --no-save solc@0.8.28`이 필요합니다.

로컬 실행:

    python -m http.server 8001 --bind 127.0.0.1
    node --test "tests/*.test.cjs"

http://localhost:8001/ 에서 실행합니다. 휴대폰 MetaMask는 PC localhost에 접근할 수 없어 앱 이동 시 실제 배포 주소를 사용합니다.
실제 기기의 카메라 권한과 MetaMask 승인·계정/네트워크 변경은 별도로 확인해야 합니다.

입장 QR(`https://bazaar.mustree.kr/`)은 기존 흐름을 유지합니다. 가게 받기·충전 QR은 목적지와 주소를 담은 사이트 URL(`open=1`)을 사용합니다. 일반 브라우저에서는 설치·복귀 안내를 먼저 표시하고 `metamask://dapp/...`으로 앱 실행을 한 번 시도합니다. 자동 실행이 차단되면 ‘앱에서 이어하기’를 직접 누릅니다. 설치 링크는 새 탭에서 열리며, 지갑 생성/가져오기 후 원래 탭으로 돌아와 같은 목적지의 이어하기 버튼을 누릅니다. 앱 안에서는 공통 지갑 컨트롤러가 계정 연결·Mustree 추가·전환을 처리합니다. 기존에 인쇄한 `link.metamask.io` QR에도 이 복귀 안내를 제공하려면 새 QR로 교체해야 합니다.

도구:

- `node tools/compile-wmst.cjs`: contracts/wMST.sol을 컴파일해 contracts/wMST.artifact.json과 wmst-artifact.js를 생성
- `node tools/estimate-wmst-gas.cjs`: 배포·키 없이 상태 오버라이드로 배포·전송·충전 gas와 수수료 정책 값을 추정해 measurements/wmst-gas-estimate.json에 기록
- `node tools/measure-rpc.cjs`: 공개 RPC 응답 시간 측정

## 지갑 진단과 기기 검증

실제 지갑 페이지 아래의 ‘지갑 연결 · 진단 기록’에서 기록을 확인하고 복사할 수 있습니다. 클립보드가 차단되면 텍스트를 선택해 수동 복사합니다. 실패 단계, 응답받은 체인 ID, 원본 및 중첩 오류의 코드·메시지, 받은 거래 해시를 기록합니다. 진단은 같은 탭의 sessionStorage에 최대 200건 보관하며 서버로 전송하지 않습니다. 요청 파라미터·서명·비밀키·시드 구문·원본 error.data는 저장하지 않고, 오류 메시지의 긴 hex와 민감정보 표식도 가립니다. 따라서 민감정보를 포함한 오류 메시지는 일부가 가려질 수 있습니다.

손님 화면의 오류 문구는 어떤 오류인지 구분할 수 있게 유지하되 체인 용어를 쓰지 않고, 충전·설정·현황 화면의 운영자용 문구는 wMST·MST·수수료 같은 용어를 쓰되 코드 식별자는 쓰지 않습니다.

자동 테스트는 모의 EIP-1193 provider와 실제 지갑·결제 컨트롤러로 다음을 검증합니다: 잘못된 네트워크 진입 후 추가·전환·결제, 일반 전송 오류 후 수동 전환과 계정 변경·재시도, 승인 취소·대기 상태의 복귀·페이지 이동·명시적 재시도, 받은 해시의 새로고침 복구와 중복 전송 차단, 영수증 조회 실패·타임아웃·잘못된 체인, 진단 복사 및 민감정보 제외, 토큰 호출 데이터와 수수료 정책, 로그 기반 내역과 잔액 역산, 운영 현황 집계, 설정 페이지의 발행·측정 계산. 이 검증은 실제 Android MetaMask 동작을 대신하지 않습니다.

갤럭시 MetaMask에서는 배포 후 실제로 다음을 확인해야 합니다.

1. setup.html에서 발행과 측정이 끝나고 설정을 반영한 뒤, 가게 QR을 열어 Mustree 미등록/다른 체인 상태에서 연결·추가·전환 창이 표시되고 소액 결제가 되는지 확인합니다. MetaMask 확인 창이 요청한 수수료 상한(“사이트 제안”)을 쓰는지, 거부한다면 측정 결과의 수수료 상한이 반영됐는지 확인합니다. 개인 지갑·가게·직원 충전 진입도 각각 확인합니다.
2. 승인을 취소하거나 대기 상태로 두고 앱 복귀·계정/네트워크 변경·페이지 이동을 해도 팝업이 반복되지 않고, 명시적 재시도로 복구되는지 확인합니다.
3. 첫 실패 후 수동으로 Mustree를 선택하고 재시도합니다. 실패하면 진단을 복사해 실패 단계·실제 체인·원본 오류를 확인합니다.
4. 거래 해시 수신 후 회선을 끊거나 앱을 닫아 결과 조회를 실패시킨 뒤 복귀/새로고침합니다. 새 전송 승인 없이 기존 해시 결과만 확인하고, 지갑의 실제 전송 횟수도 한 번인지 확인합니다.
5. 충전받은 손님 지갑으로 결제를 20회 반복해 수수료가 모자라지 않는지, 운영 현황의 수수료 잔여 횟수가 함께 줄어드는지 확인합니다.
6. Android 클립보드 권한과 진단 수동 복사, 연결 승인 중 앱 전환, MetaMask의 실제 계정·체인 이벤트 및 뒤로 가기 캐시 복원을 확인합니다.
