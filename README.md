# MST 파운데이션 달란트

빌드 단계 없이 동작하는 HTML/CSS/JavaScript 서비스입니다. QR 생성·인식 라이브러리는 vendor/에 포함되어 있습니다.

## 화면과 공통 구조

- index.html: 개인 지갑 잔액, 충전용 받기 QR, 최근 거래
- operator.html: 직원이 현금을 받고 손님 지갑으로 충전 송금
- pay.html: 가게 결제 또는 mode=transfer인 일반 MST 송금
- store.html: 가게 받기 QR, 잔액, 최근 거래, 공통 송금 화면으로 이동
- merchant.html: 연결 없이 주소를 입력해 가게 받기 QR 생성

송금은 역할에 관계없이 transfer-core.js의 검증·전송·영수증 확인을 사용합니다.
transfer-page.js가 지갑 연결과 송금 상태를 관리하고 payment-ui.js가 공통 입력·대기·완료 화면을 만듭니다.
금액 계산과 충전 보너스·가스비 지원 정책도 transfer-core.js에서 처리합니다. 결제·충전 페이지는 HTML의 data-transfer-kind로 역할만 지정합니다.
QR 카메라·이미지 인식은 qr-scanner.js, QR 생성과 금액·주소 표시는 payment-ui.js로 통일했습니다.
개인·가게 내역의 조회와 계정별 갱신은 transaction-history.js, 표시는 payment-ui.js를 공유합니다.
계정이 바뀌거나 연결이 해제되면 이전 내역 응답은 무시하며 조회 실패를 빈 내역으로 표시하지 않습니다.

## 송금 정책

| 종류 | 입력 | 송금액 |
| --- | --- | --- |
| 가게 결제 | 원화 정수, 최대 10,000,000원 | 1,000원 = 1 MST |
| 직원 충전 | 1원 이상, 1원 단위 | 10% 보너스 및 기존 수령자 가스비 지원 정책 적용 |
| 일반 송금 | MST, 소수 셋째 자리까지 | 입력한 MST |

실제 모드에서는 MetaMask 승인을 통해 네이티브 MST를 전송합니다.
계정·네트워크를 잔액 조회 전후로 재검증하고, 잔액 조회 실패 시 공개 RPC 조회를 지원합니다.
송금 결과 확인이 지연되면 기존 거래 해시만 다시 확인하며 새 송금을 막습니다.
잔액은 모든 화면에서 소수 셋째 자리까지 같은 방식으로 반올림하지만 실제 송금 계산은 정확한 wei를 사용합니다.
거래 내역은 최초 조회 시 최근 1,200개 블록을 확인하고, 이후에는 마지막 조회 완료 블록 다음부터 최신 블록까지 조회합니다. 표시 건수와 관계없이 요청 범위를 모두 확인한 후에만 완료 블록을 갱신합니다. RPC 오류가 나면 기존 내역과 완료 블록을 유지합니다.
내역 RPC의 각 HTTP 요청은 응답 본문 수신까지 8초로 제한합니다. 조회가 실패하면 오류 알림 없이 같은 완료 블록부터 한 번 더 시도하며, 총 두 번 실패했을 때 오류 안내와 ‘다시 확인’ 버튼을 표시합니다. 이전 오류 안내는 재시도 중에도 유지하고 버튼을 잠시 비활성화하며 성공할 때 해제합니다. 실패 기록은 재접속 후에도 유지하여 잔액이 같아도 재조회를 생략하지 않습니다. 과거 잔액만 조회할 수 없는 경우에는 기존처럼 해당 잔액만 —로 표시합니다.
체인·계정별 localStorage에 최근 24시간 내역 최대 200건, 조회 완료 블록, 그 블록의 정확한 wei 잔액, 확인 시각을 함께 저장합니다. 기존 v1 내역 캐시도 최초 동기화 시 병합합니다. 개인 화면은 최근 5건, 가게 화면은 최근 20건을 표시합니다. 미리보기 내역은 저장하지 않습니다.
페이지 진입·복귀 시 현재 잔액을 조회하되, 이전 동기화 잔액과 같고 60초가 지나지 않았으며 미확인 전송 hash가 없으면 거래 내역 RPC를 생략합니다. 지갑·가게 화면이 보이는 동안에는 60초마다 잔액과 내역을 확인합니다. 잔액 새로고침과 내역 재시도는 잔액 변화와 관계없이 내역을 확인합니다. 숨겨진 페이지에서는 정기 요청을 보내지 않습니다.
직접 보낸 tx hash는 MetaMask에서 받은 즉시 별도 localStorage에 체인·발신 계정별로 저장합니다(24시간, 최대 200건). 미확인 hash는 다음 내역 갱신에서 영수증을 확인하며 최초 블록 범위 밖의 성공 거래도 hash로 복구합니다. 대기 중인 hash는 다음 확인 대상으로 유지하며 실패한 거래는 성공 내역에 넣지 않습니다.
내역의 잔액 열은 해당 블록 종료 시점의 잔액입니다. 과거 잔액을 제공하지 못하는 RPC 응답은 해당 잔액만 —로 표시하고 거래는 유지합니다.
저장 내역은 같은 브라우저에서만 유지됩니다. 다른 기기나 브라우저와 동기화되지 않으며, 브라우저 데이터 삭제 시 초기화됩니다. 완료 블록이 없는 최초 접속·저장소 초기화 시에는 최근 1,200개 블록과 저장된 전송 hash만 조회합니다. 저장된 완료 블록이 있으면 장기 미접속 기간도 이후 블록부터 이어서 확인합니다. 표준 블록의 from/to 기준인 네이티브 송금 내역이며 컨트랙트 내부 송금 추적은 포함하지 않습니다.

## 지갑 연결

- 서비스: https://bazaar.mustree.kr/
- 최초 방문 시 사용자 동작 없이 계정 접근 승인을 요청하지 않습니다.
- 연결된 계정과 Mustree 네트워크는 추가 승인 없이 복원합니다.
- 모바일 일반 브라우저는 MetaMask 내부 브라우저로 이어집니다.
- 네트워크 설정은 wallet.js의 NETWORK에서 관리합니다.

RPC: https://block.mustree.kr, Chain ID: 7601 (0x1db1), 기호: MST, decimals: 18.

RPC 타임아웃은 `node tools/measure-rpc.cjs`로 실제 엔드포인트를 순차 측정해 설정했습니다. 원시 기록은 measurements/rpc-latency.json에 있습니다. HTTP 요청 61회 모두 성공했고, 100개 블록 묶음 12회의 최대 응답은 31.7ms, 최신 잔액 12회의 최대 응답은 1,014.9ms였습니다. 모바일 회선과 일시적인 지연에 여유를 두기 위해 공개 RPC 잔액 조회와 내역 조회에 요청당 8초를 적용했습니다. MetaMask provider 요청의 기존 12초 제한은 유지합니다. 이는 PC에서 약 8초 동안 측정한 표본이며 모바일 회선·혼잡 시간대 성능을 보장하지 않습니다. 최근 1,200개 블록에 거래가 없어 영수증·거래가 많은 블록의 성능은 이번 표본에 포함되지 않았습니다.

## 미리보기와 테스트

각 화면 URL에 ?preview=1을 붙이면 실제 지갑 조회·승인·송금 없이 공통 UI를 확인할 수 있습니다.
개인 지갑 미리보기는 상태 선택기로 승인·취소·실패·지연 상황을 재현합니다.
미리보기 QR은 실제 송금에 사용할 수 없는 안내 그림입니다.

로컬 실행:

    python -m http.server 8001 --bind 127.0.0.1
    node --test tests/*.test.cjs

http://localhost:8001/ 에서 실행합니다. 휴대폰 MetaMask는 PC localhost에 접근할 수 없어 앱 이동 시 실제 배포 주소를 사용합니다.
실제 기기의 카메라 권한과 MetaMask 승인·계정/네트워크 변경은 별도로 확인해야 합니다.
